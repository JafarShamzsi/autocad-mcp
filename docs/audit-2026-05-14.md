### Feature pack
| Feature | What it does |
|---------|-------------|
| F6 — units propagation | `arch.room` (and the rest of the area-bearing ops) picks SF / m² based on `$INSUNITS`. All three backends. Unitless drawings fall back to "SF" so historic callers see no change. |
| Hatch library | `arch.list_hatches` returns ~18 curated AEC patterns (BRICK, CONCRETE, INSULATION, WOOD, EARTH, etc.); `arch.hatch_region` applies one to a closed polygon. All three backends. |
| XREF mutation | `xref_attach` / `xref_detach` / `xref_reload` / `xref_bind` ops on the `project` tool. attach + detach work on ezdxf; reload + bind are COM-only. The detach op refuses non-XREF blocks (DXF flag 4 check). |
| Layout / paperspace ops | `drawing.list_layouts`, `create_layout`, `set_active_layout`, `create_viewport` on all three backends. |
| Block import from external files | `block.list_from_file` + `block.import_from_file` — read an external .dwg/.dxf, copy block definitions into the active drawing. Skips existing names; uses ezdxf's `Importer` with `rename=False`. |
| **External block-library indexer** | `library.scan_external` walks a directory tree, extracts every non-anonymous non-XREF block, writes to SQLite. `library.search_external` filters by name / prefix / file. `library.stats_external` summarizes. Smoke-tested against 5 DWGs from `furniture and details/`: **269 blocks indexed**, no failures. This is the unlock for "build any kind of building with vendor assets." |

### F1 — per-tool permission grants
Decision: not buildable today. Claude Code's plugin spec doesn't expose
per-operation permission grants in `plugin.json`. The right shape would
be splitting `system` into a read-only tool + a write tool once the
spec supports it. Documented in README's `system` section.

## Decisions on the deferred items

### H4 — file_ipc PostMessage trigger on full AutoCAD 2027
**Intentionally closed without a code change.** Rationale:
- Auto-mode (the default) detects full AutoCAD via the registry and
  picks the COM backend, which works correctly.
- Explicit `AUTOCAD_MCP_BACKEND=file_ipc` against full AutoCAD now
  refuses upfront with a clear error pointing at COM (`category=not_supported`).
- The "fix" would be a named-pipe server inside AutoCAD's process —
  ~500 LOC of .NET to make a code path nobody actually hits work. The
  architectural cost (a third IPC mechanism alongside COM and file-IPC)
  exceeds the value.
- If a future user reports an actual need (e.g. an MCP client that must
  bypass COM for license-isolation reasons), revisit.

### G5 — .NET ManagedReactor replacing the LISP `vlr-commandended` workaround
**Shipped this session.** New `dotnet/MCPReactor/` project follows the
same scaffolding as `SheetSetReader`:

- Subscribes to `Database.ObjectAppended` / `.ObjectModified` /
  `.ObjectErased` directly — no forward-scan workaround needed.
- Subscribes to `Document.CommandWillStart` / `.CommandEnded` /
  `.CommandCancelled`.
- Subscribes to `Document.ImpliedSelectionChanged` for `selection_changed`
  events — surface the LISP reactor couldn't reach.
- Emits the same JSON-Lines schema (`ts`, `ts_local`, `kind`, `handle`,
  `entity_type`, `layer`, optional `command` / `count` / `first_handle`)
  to `<ipc-dir>/autocad_mcp_events.log` so `EventTail` works unchanged.
- Three AutoCAD commands registered after NETLOAD: `MCPATTACHREACTOR`,
  `MCPDETACHREACTOR`, `MCPREACTORSTATUS`.
- `events.start_recording` auto-picks .NET when backend=COM and the DLL
  is on disk; falls back to LISP if NETLOAD fails. Override with
  `data: {"prefer": "lisp"}` if you specifically want the LISP path.
- Prebuilt DLL ships at `bin/dotnet/MCPReactor.dll` (~7 KB), tracked in
  the repo via the same `!`-exception as `SheetSetReader.dll`.

Verified:
- `dotnet build -c Release dotnet/MCPReactor/MCPReactor.csproj` → 0 errors
  against AutoCAD 2027 + .NET 10.0.300.
- 5 new tests in `test_n_fixes.py` cover: DLL presence, csproj probe-driven
  paths, command-method declarations, schema-field match against the LISP
  reactor, and the path-picker contract.
- 3 new tests in `test_events.py` cover: explicit `prefer="lisp"` path,
  auto-mode preferring .NET when DLL exists, and auto-mode falling back to
  LISP when DLL is missing.

Live smoke harness shipped at `scripts/smoke_dotnet_reactor.py` — when an
AutoCAD instance is running and a document is open, it drives the full
NETLOAD → attach → drawing → event-replay cycle. Couldn't run during
this session (no live AutoCAD instance), but the script is the canonical
verification step for a maintainer with one.
