### Bonus fixes discovered this session

- **Standalone .NET path is dead** — the original advisor-recommended
  spike for a CLI-style `.dst` reader proved that `AcSmSheetSetMgr`
  outside AutoCAD's process exposes only `IUnknown` (`QueryInterface`
  for `IAcSmSheetSetMgr` returns `E_NOINTERFACE`). NETLOAD'd-in-process
  is the only path. The audit-2026-05-12's "Confirmed .NET-only" finding
  was correct in spirit but lacked the empirical detail — this session's
  IID probe is the authoritative verification.
- **AutoCAD 2027 ships .NET 10.0** (not .NET 8). The `acdbmgd.runtimeconfig.json`
  declares `"tfm": "net10.0"`. Targeting `net10.0-windows` works because
  the `.NET 10.0.300` SDK is present alongside `.NET 9.0.313`. Documented
  in the .csproj header so future maintainers don't downgrade.
- **`Autodesk.AutoCAD.Runtime.Exception` shadows `System.Exception`** —
  caught at first compile. Aliased `using AcRuntime = …` and explicit
  using-aliases for the two attribute types avoid the wholesale namespace
  pull that would re-trigger it.
- **The COM .dst reader auto-creates a drawing if needed** — the smoke
  test was failing on the AutoCAD "Start" tab because `Document` is null
  there. Resolved in the smoke script; the production path (called from
  the indexer) inherits whatever active document the COM backend has,
  which is the indexer's existing assumption.

## Architecture changes worth understanding

### LISP library mini-language

`arch/library/apply.py::serialize_spec_for_lisp(spec_list)` encodes a
`SYMBOL_LIBRARY` entry as a compact string the LISP renderer parses:

```
P,1,4,-9,0,9,0,9,-8,-9,-8;P,1,32,7,-12,6.86,-12.78,...
```

- Entities separated by `;`, fields by `,`.
- Leading type token: `L` line, `C` circle, `A` arc, `P` polyline, `T` text.
- Polyline format: `P,closed_flag,n_points,x1,y1,...,xn,yn`.
- Text restriction: the `text` field cannot contain `,` or `;` — Python
  raises `ValueError` at serialization time. None of the shipping
  symbols hit that, but if a new symbol's label contains those chars
  the parser needs an escape mechanism added.

The LISP-side parser is `mcp-lib-emit-entities` in `library_tools.lsp`.
It walks the spec string, dispatches per type-token, and accumulates
each drawn entity into a selection set that the dispatcher then
absorbs into `_.-BLOCK <name> 0,0 <ss> ""`. All entities go on layer
"0" so block inserts inherit the insert's layer (standard AEC
convention; matches COM + ezdxf).

### Binary `.dst` integration path

```
project/index.py::_index_sheetset
    └─ read_sheetset()                       (XML reader)
       └─ SheetSetBinaryUnsupported          (binary header detected)
          └─ _read_binary_sheetset_via_com()  (try COM fallback)
             └─ read_sheetset_via_com()       (in sheetset_com_reader.py)
                └─ win32com SendCommand → NETLOAD + MCPREADDST → JSON file
                   └─ SheetSetReader.dll inside AutoCAD's process
                      └─ AcSmSheetSetMgr → walk → JSON
```

The fallback is **opt-out by being conditional on AutoCAD running and
the DLL being on disk** — anything else (no AutoCAD, missing DLL, COM
error) re-raises the original `SheetSetBinaryUnsupported` with its
workarounds intact. The indexer never silently fails; the worst case is
a sheet set that doesn't index because the binary form needs AutoCAD
that isn't running.

NETLOAD is cached per-process via a module-level set, so a project
with many `.dst` files only pays the load cost once.

## Behavior changes (existing-user surprises)

- **Binary `.dst` indexing now succeeds if AutoCAD is running.**
  Previously, an `.acadproj.toml` that referenced a binary `.dst` would
  produce a `sheetset` error every index. Now: silent success if the
  COM path is available, identical error if not. No new failure modes;
  one previously-failing case becomes a success.
- **`library_define` / `library_insert` no longer return
  `not_supported` on file_ipc.** LT users who had been working around
  this by chaining `block_define` + `block_insert` calls now get the
  procedural symbols directly. Existing callers see the previous
  `not_supported` path replaced with real success payloads of the same
  shape COM uses (`{name, existed, entity_count}`).

## Distribution + install notes

The `.NET` DLL has to be **built once** and ends up in
`bin/dotnet/SheetSetReader.dll`. Plugin packaging should either:

1. Ship the pre-built DLL in the plugin (simplest; ties the plugin to
   a single AutoCAD major version due to the assembly's `Reference`
   hint paths) — currently in tree as `bin/dotnet/SheetSetReader.dll`.
   `.gitignore` was updated this session to make this work: the
   `bin/dotnet/` directory and its `*.dll` contents are explicitly
   tracked via `!`-exceptions, while `dotnet/**/bin/` (per-project
   build artifacts) is ignored.
2. Run `dotnet build` on plugin install. Requires .NET 10 SDK on the
   user's machine.

For now option 1 is the path; the prebuilt DLL is in the repo and the
indexer auto-loads it.
