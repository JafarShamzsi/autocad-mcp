## Behavior changes (existing-user surprises)

These are improvements, but they shift behavior in ways an existing user
might not expect:

- **N13 — `drawing(operation="create")` on file_ipc** previously clobbered
  the active drawing silently. It now refuses when `DBMOD != 0` unless
  the caller passes `force=true`. Existing LT scripts that called
  `create` on a dirty drawing as a "reset to blank" idiom will now see
  an error instead of an overwrite. The new contract is safer; callers
  that want the old behavior add `data={"force": true}`.

## Manual smoke-test required after first install

The LISP changes (`mcp_reactors.lsp`, `mcp_dispatch.lsp`, new
`pid_tools.lsp`) have only static / file-presence tests. They cannot be
exercised without a running AutoCAD LT 2024+. Once on a real machine,
verify:

1. `(load "mcp_dispatch.lsp")` reports `MCP Dispatch v3.2 loaded` and
   either `MCP P&ID tools v3.2 loaded` *or* the actionable message about
   adding `lisp-code/` to the Support File Search Path.
2. `(c:setup-pid-layers)` creates the 7 PID-* layers without errors.
3. `(c:mcp-attach-reactors)` then drawing a line emits one event line
   into `<ipc-dir>/autocad_mcp_events.log` with a parseable JSON object
   and a `ts_local` field.
4. The Python side then `events(operation="recent")` returns that record.

**Bonus fixes discovered while doing the above:**

- **COM iteration flake** — `for l in doc.Layers` raised "This object does not support enumeration" on first use after a fresh Python process, which surfaced as a flaky `test_setup_layers_then_wall` in the full integration suite. Root cause: `GetActiveObject` returns a late-bound dispatch whose typelib isn't always cached; iteration breaks until pywin32's `gencache` has been populated. Fix: wrap the dispatch via `gencache.EnsureDispatch` at attach time. Falls back to the raw object if gencache fails so we never get worse than the prior behaviour.
- **`library_define` flake on COM** — `doc.Blocks.Item(name)` for a missing-name return varies between raising and returning a stale handle after gencache. Replaced with iteration-based existence check, and made both "existed" and "new" branches return `entity_count` so callers don't have to branch on shape.
- **pid_tools.lsp live smoke** — Verified all 11 `c:` functions end-to-end against AutoCAD 2027 via `scripts/smoke_pid_tools.py`. Every function produces the expected entity count (e.g. `c:insert-instrument` → 3 entities = circle + crosshair + label). No `(command "_.-LAYER" _M ... _C ...)` arg-count bugs lurking.
- **Remaining COM/file_ipc error returns now carry `category`** — `com_backend` init failure (`backend_unavailable`), status without init (`backend_unavailable`), status read errors (`internal_error`), screenshot-provider-missing (`backend_unavailable`), `file_ipc` dispatch timeout (`timeout`), `file_ipc` screenshot failure (`internal_error`). Closes the remaining audit bullet under Q5 on the COM side.

## Still open

### Feature-shaped gap (concrete work, not blocked by spec)

- **G3 / N9 — `library.*` not wired to LISP/file_ipc.** Python side returns
  a clear `category="not_supported"` error with workarounds (use COM,
  use ezdxf, define blocks manually). Real fix: port the eleven `c:`
  helpers from `pid_tools.lsp` pattern to a sibling `library_tools.lsp`
  that walks `SYMBOL_LIBRARY` and emits `_BLOCK` / `_INSERT` commands.
  Only feature-shaped gap remaining. Estimated 1–2 hours of LISP work.

### Blocked by external constraints

- **H4 (partial)** — `PostMessageW(WM_CHAR)` is fundamentally unsupported
  on full AutoCAD 2027 (DirectX-rendered command line — no Win32 EDIT
  target). The file_ipc backend now refuses upfront on full AutoCAD; the
  *real* fix would need either a .NET-backed pipe trigger or a LISP
  timer-reactor that polls for cmd files (no AutoLISP timer surface
  exists in core).
- **Binary `.dst` decoder** — Requires `AcSmSheetSetMgr` which is .NET /
  ObjectARX only; not callable from AutoLISP COM (verified by
  `scripts/g6_probe_lisp_acsm.py`). Detection + clear error shipped.
- **G5 (partial)** — `vlr-acdb-reactor :vlr-objectappended` doesn't fire
  on AutoCAD 2024+. Compensated via a `:vlr-commandended` scan that
  emits object_appended for handles past a high-water mark. Limitation:
  entities added via `entmake` outside a command boundary won't fire.

### Forward-looking (features, not bugs)

- **F1** — `tools.json` for per-tool permission grants. Depends on
  Claude Code's plugin spec for selective auto-allow.
- **F5** — Replace LISP reactors with a .NET ManagedReactor for richer
  events (selection-changed etc.). Requires .NET project + ARX loading.
- **F6** — Drawing-units propagation through composite ops (`"SF"` vs.
  `"m²"`, MText hardcoded `+2` offsets, scale-bar `0.25` bar height).
  Substantial because every `arch.*` composite needs an opinion.

### Intentionally not changed

- **Q1** — Remaining `except Exception:` blocks have legitimate
  "expected miss" behaviour (Layer/Block/Item lookups, GetVariable
  failures, getattr fallbacks). Logging them at debug would be noise.
- **Q5 (COM-side)** — `_run` infers `category` from RuntimeError wording
  via a substring map with 10 unit tests; init/status/screenshot now
  pass `category` directly. The remaining inferences cover ~20+ raise
  sites without per-site changes. A deeper refactor (custom exception
  subclasses carrying category) is unnecessary now.
- **Q6** — `_NON_SHEET_CONTAINERS` hand-curated set. The real .dst format
  is binary anyway (G6 finding); the XML branch only kicks in for
  user-authored XML or older AutoCAD output, where the curated set is
  battle-tested.
- **Q8** — `door_geometry` tie-break documented in the function docstring.
